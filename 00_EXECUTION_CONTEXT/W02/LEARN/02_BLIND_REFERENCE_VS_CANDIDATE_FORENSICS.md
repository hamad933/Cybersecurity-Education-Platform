## Blind-audit rule

## Overall workstation composition
The owner reference is a dense dark learning workstation with five meaningful regions. LEFT is an ordered journey; CENTER is a deep active learning surface; RIGHT is a dense contextual inspector; BOTTOM exposes multiple deep-work channels; TOP/local header carries compact context/actions. The current candidate instead appears as a rounded, padded page nested inside the shared workspace. The geometry is not merely "sparse": the nested frame, generous padding, repeated cards, shallow RIGHT, closed single-purpose BOTTOM, and fixture-thin CENTER jointly reduce workstation density.

## Region-by-region blind decomposition
### TOP
Reference: compact local action/context layer integrated with the workstation. Current: no real shared TOP consumption; resume/status live inside CENTER. Material deltas: region ownership, action hierarchy, vertical chrome, route/current-activity orientation.

### LEFT
Reference: previous/current/next journey, current unit expanded into activity/section progression, strong connected state grammar. Current: current-unit outline only, duplicated `Test Section`, shallow 1/1 progress, Practice/Assessment/Lab status appended below. Material deltas: pathway orientation, journey continuity, selected state, state semantics, activity hierarchy, duplicate node, progress vocabulary, visual density.

### CENTER
Reference: one dominant selected lesson/activity with objectives, explanation, code, callouts and deep content. Current: tiny `Test Section` body, broad blank plane, then permanent sibling cards for Practice/Assessment/Lab. Material deltas: active-surface ownership, center dominance, content richness, dead-space distribution, typography/vertical rhythm, focus hierarchy.

### RIGHT
Reference: deep contextual information including objective, prerequisites, recommendation, lab readiness, sources/knowledge/evidence-like contexts and quick access. Current: sparse cards, often empty prerequisites and a source label such as `C1`. Material deltas: contextual depth, provenance visibility, objective, readiness, recommendation ownership, quick access, grouping/density.

### BOTTOM
Reference: a meaningful deep-work band with multiple channels/counts. Current: one local collapsed bar with generic label and a small set of summary cards when expanded. Material deltas: deep-work breadth, channel affordance, counts, ownership, contextual utility.

## Cross-cutting visual findings discovered blind
- Excessive card/rounded-container grammar creates equal visual weight across unrelated information levels.
- Borders substitute for hierarchy where dense separators/rows would be more efficient.
- Typography and padding consume disproportionate vertical space for the amount of information presented.
- Emoji-based global W02 iconography is visually platform-dependent and weakens enterprise consistency.
- Secondary navigation behaves like pill cards rather than a compact desktop tab strip.
- Outer margins and nested panel widths reduce effective CENTER/RIGHT real estate at 1440.
- Current screenshot cannot prove rich Bidi behavior because the fixture is not representative.

## What is not a blind visual defect by itself
- Do **not** copy Save/Undo/editor controls from the reference into Learn: `CONTRACT_OVERRIDES_IMAGE` because Library/Unified Editor owns canonical editing.
- Do **not** invent the reference's 28% overall journey value: `AUTHORITY_DECISION_REQUIRED` until denominator/completion semantics exist.
- Do **not** fabricate executable Assessment or Lab actions: current architecture explicitly lacks those authoritative integrations.
- Exact color shade or icon glyph parity is not required pixel-for-pixel; however the *systemic use of platform-dependent emoji* is a separate consistency finding, not a request to copy the reference icons literally.

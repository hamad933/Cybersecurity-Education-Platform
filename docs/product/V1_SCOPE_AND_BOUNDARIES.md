# v1 Scope and Boundaries

Status: **candidate**. Scope IDs and acceptance methods are normative in `planning/task004/V1_SCOPE_MATRIX.tsv`.

## Included in v1

- Local single-owner authentication and protected sessions.
- Immutable source custody, safe registration/import, extraction state, stable anchors, authority review, and provenance.
- Singular canonical knowledge, typed blocks, drafts, review decisions, immutable published revisions, comparison, impact, and restoration.
- The 16-Domain expansion architecture with bounded seed content only; capability-centred paths, diagnostics, micro practice, Guided Simulator Labs, evidence, mastery, and failure review.
- Persistent Enterprise Catalog, versioned baselines, visual Scenario Studio, portable Scenario Packages, isolated Scenario Runs, deterministic replay/reset, and simulated evidence.
- Evidence and Portfolio records with explicit origin and integrity metadata.
- Manual AI Bridge export/import/validation/human-review workflow only.
- PostgreSQL full-text search, database-backed queue, local file/object abstraction, audit, import/export, and verified backup/restore.
- Arabic-first responsive interface with correct mixed RTL/LTR treatment and keyboard-accessible workflows.
- Deep delivery through VS-001, VS-002, VS-003 and integration/hardening.

## Explicitly not implied by v1

- Finished curricula for all 16 Domains or promotion of all 96 provisional KUs.
- Externally verified technical truth for every claim, calibrated mastery thresholds, or real-world job competence.
- Real offensive execution, production SIEM/SOAR/GRC/EDR/scanning, or real-execution connectors.
- Automated/provider/API/local-model AI, provider credentials, embeddings, or vector search.
- SaaS multi-tenancy, public registration, billing, social features, marketplace, Internet collaboration, microservices, Kafka, Kubernetes, graph database, dedicated search cluster, or Redis dependency.

## Completion rule

v1 is complete only when every `IN_V1` scope row has later implementation evidence, all three vertical slices traverse the agreed lifecycle, backup/restore and accessibility gates pass, unresolved technical-claim blockers remain correctly bounded, and the release candidate is externally approved. Document presence alone is never completion.

## Change control

Moving a deferred item into v1 requires an approved decision with acceptance impact, owning module, security review, dependency impact, and updated traceability. Silent scope expansion is prohibited.

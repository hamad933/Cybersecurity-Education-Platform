# User Profiles and Journeys

## Bounded v1 profiles

| Profile | Goal | Pain points addressed | v1 authority |
|---|---|---|---|
| Local owner / learner-author | Build defensible capability from private sources and practise safely | Fragmented material, weak provenance, passive completion, environment overhead | Full local workspace authority; cannot bypass publication/audit rules |
| Curriculum reviewer persona | Check source support, teaching boundary, and revision diff | Generated content presented as truth; lost conflicts | Workflow role performed by owner in v1; separate accounts deferred |
| Scenario designer persona | Model institutional decisions and evidence | Static labs, reset cost, simulation/real confusion | May author versions; Run state never changes baseline |
| Professional reviewer persona | Judge evidence relevance and transfer boundary | Percent-complete metrics; unclear origin | May accept/reject evidence through owner workflow; no external claims |

Application permissions protect product records. Simulated professional roles affect only scenario rules and never grant application access.

## Journey J-01 — source to publication

Select authorized file -> preview declared scope -> quarantine and validate -> preserve original/digest -> extract representation -> inspect warnings and anchors -> assess authority -> review claims/relationships -> draft canonical revision -> compare -> approve/reject -> publish immutable revision -> audit. Any failed stage preserves the original and last published revision.

## Journey J-02 — lesson revision

Open published lesson -> switch to structured edit without losing context -> create draft -> insert/reorder validated blocks -> attach citations -> compare with published -> resolve warnings -> approve -> publish new immutable revision -> impact dependent practice/labs. Restore means republishing a new revision based on an older one.

## Journey J-03 — daily capability loop

Daily queue explains selection -> learner studies bounded lesson -> completes micro practice -> starts simulator lab -> receives positive/negative consequences -> submits evidence -> mastery rule evaluates -> failure creates specific review -> later retention check validates transfer.

## Journey J-04 — enterprise scenario

Choose Enterprise Baseline Revision -> create Scenario Definition draft in Studio -> bind catalogs and validation rules -> publish definition -> fork isolated Run -> select simulated role/device -> act -> inspect deterministic trace -> remediate/verify -> collect `SIMULATED` evidence -> reset/replay -> optionally propose a baseline change for separate review.

## Journey J-05 — Manual AI Bridge

Create Prompt Package -> select visible source segments and requested schema -> export manifest/digests -> mark awaiting manual processing -> user processes manually in ChatGPT Plus -> import package -> verify digest/schema/source references -> inspect entity diffs -> human partially accepts/accepts/rejects -> create drafts only -> publish through normal review.

## Journey J-06 — recoverability

Choose backup scope -> exclude/secure secrets -> create manifest and hashes -> verify archive -> stage restore into isolated target -> validate DB/blob consistency -> approve cutover or abandon -> retain audit evidence.
